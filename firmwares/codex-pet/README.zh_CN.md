# Codex Pet

240×320 Codex 桌面伙伴：居中的 Bloub 云朵、纯文字剩余额度百分比，以及可展开的结果区域。Mac/Rust/BSP、采集器、USB/BLE 身份与配对继续共享；桥接同时分发等待提醒并调整 token 单位边界的舍入。

已选通知音：**成功 L**（解谜成功，2.247 秒）、**等待 N**（希卡感应器，0.810 秒）、**停止／失败 V1**（Game Over，升高 7 个半音、保持原速、截尾至 2.25 秒）。失败音通过去掉尾端缩短，没有加快旋律。选定的源 WAV 和来源记录保存在 `assets/sounds/`。全部为 16 kHz 单声道，波形峰值保持原有 3000/32767 上限，端点淡入淡出 5 毫秒；编解码器音量为 65%。尚未测量扬声器实际响度／音色。保留两秒冷却。`tools/bake_sound.py` 将不同长度的 PCM 预存至 Flash，播放只使用一个 512 字节缓冲区，不进行实时合成。主机测试检查全部预存采样和源文件哈希。

`waiting-alert-v1` 增加类型 3 和 WAITING。本机与远端通过实时 hook 检测授权和输入请求，每次等待提醒一次。OK 仅关闭设备通知。见 [hooks 配置](../../docs/hooks.zh_CN.md)。

## 使用

- **主页：**云朵中心位于 y=154；结果到达后在 380 毫秒内上移到 y=99。下方显示最新中文标题，工作区和耗时共用一行。橙色标题为 `DONE`，多条时为 `DONE (2 UNREAD)`；停止/失败显示 `STOPPED`。取消固定右上角未读点，保留原动画自带的小点。
- **消息栈：**最新消息优先，最多保存八份不可变快照。每次露出的结果在主页显示 15 秒后自动出栈；信息页和画廊暂停计时。在这些页面收到新消息只入栈，不切换页面。重复投递不重置计时、不重播声音、不恢复已移除消息。满额淘汰最旧项，重启清空。
- **UP/DOWN：**双向循环切换“主页 → 额度/重置 → 7 日 token → 连接/系统”。信息页保持显示，直到按键切换。
- **OK：**在主页确认一条结果并眨眼；剩余消息继续展开。在信息页只回主页，不确认消息。无未读时触发友好眨眼。
- **长按 OK：**回主页，不确认消息。**长按 UP：**进入六组序列诊断画廊，UP/DOWN 浏览，OK 退出。

主页右下角只显示最长有效周期的额度，例如 `94%  2d 04h`；缺失或过期时隐藏。重置页显示该周期的大百分比、倒计时、另一个有效周期、重置卡数量，以及最多六行有效期/状态。未知卡片详情会明确标注。这些页面只读，不会消耗重置卡。连接/系统页显示传输方式、距上次状态更新的时间、来源健康、实际电量（不可用时 `--`）、当前亮度、固件版本、运行时长和软件 FPS。

Token 页复用现有账号 `account/usage/read` 数据链路，桥接每小时查询。七个自然日截止于接口最近返回的日期，可能是昨天；页面明确标注截止日期。缺失日显示 `--`，真实零值显示零；任一天缺失时不伪造七日总量。过期或断开时隐藏旧值。不到十亿用 M，达到后 B 固定一位小数（`1.0B`、`1.2B`）；每日数字和单位上下分行。现有四字符协议值仍有舍入，超出列宽的极大数值以省略号显示。桥接不再把未达到十亿的 999.xM 提前舍入成 B。

背景为浅灰白（`#ECECEC`）、深色云朵；Montserrat 采用 11/13/18/34/60 像素抗锯齿字形。中文复用桥接生成的位图，过长工作区名称在耗时之前截断并加省略号；紧凑状态标签使用英文。结果表示当前一轮回复结束，不代表整个项目完成或测试成功。保留两秒内声音合并；其他任务仍在运行时，当前消息继续保持对应动画；最后一条出栈后恢复工作/待机/离线状态。

主页左下角：播放图标加运行中的任务数；空闲时左下角留空；连接断开或来源异常仅断链图标，不显示 `0` 或 `--`。右下角百分比使用深色 18 像素 Montserrat，倒计时使用灰色 13 像素，数字基线对齐，任务数变化独立于未读动画刷新。

## 自动息屏

背光分四档：有未读消息或新消息时为 85%；有运行任务但无消息时为 50%。两者都没有时，闲置第一分钟为 85%，满一分钟降至 35%，满一小时息屏并暂停渲染。运行任务、未读消息、新消息和按键重置闲置计时；心跳、元数据与重复消息不重置。消息优先于运行状态。息屏后的首次按键只唤醒，保留页面和未读状态；完整绘制一帧后恢复对应亮度。USB/BLE 保持接收，断连后最近已知的正数运行任务仍保守地保持 50%。这是显示息屏，不是 MCU 深度睡眠。

## 选定序列

全部使用云朵形状和未修改的上游引擎：

| 状态 | 序列（秒） | 结束行为 |
| --- | --- | --- |
| 待机 | 无趣 5 → 旋转 4 → 玩耍 4 → 困倦 5 | 循环 |
| 工作中 | 专注 6 → 思考 3 → 睁大眼睛 6 → 思考 3 → 好奇 6 | 循环 |
| 完成 | 通知冒点 2.2 | 动态通知尾段保持到消息出栈 |
| 确认 | 眨眼 3 → 兴奋 3 | 返回当前实时状态 |
| 停止/失败 | 惊讶 2.5 → 警觉 3 | 动态末态尾段保持到消息出栈 |
| 离线/来源异常 | 受惊 2.4 → 感叹号 4 | 循环 |

工作序列以好奇表情结束，眨眼留给确认回应。Notify 冒点一次后循环四秒动态尾段，没有固定 20 秒超时。OK 完整播放六秒确认回应，再回到下一条未读或当前实时状态。期间新结果继续入栈，连续 OK 可移除消息，但不重启动画。露出更早的完成消息时不重播冒点。消息持有头像期间，连接/来源警告仍可见。

循环序列追加 450 毫秒，直接形变回首个表情；最后 150 毫秒烘焙混合用于闭合眨眼、呼吸和视线的相位差。完成和停止各有四秒动态尾段；`alert` 末态是上游倾斜感叹号。内部切换不绕回中性。动作之间直接调用上游切换接口；原先在 wide → thinking 中瞬间插入 idle 会丢失眼睛的离开位置，现已修正。任意事件中断使用 140 毫秒实时像素混合。表情是粗粒度真实状态下的表演，不代表具体工具阶段。来源断开不显示成功。

## 构建与安装

通过 `scripts/firmware.py new codex-pet` 从空白模板创建。请阅读根目录[工作区指南](../../docs/firmware-workspaces.zh_CN.md)。

```bash
cargo test --manifest-path rust-bridge/Cargo.toml
cargo build --release --manifest-path rust-bridge/Cargo.toml
npm ci --prefix firmwares/codex-pet/tools
node firmwares/codex-pet/tools/bake.mjs
node firmwares/codex-pet/tools/bake_icons.mjs
.venv/bin/python firmwares/codex-pet/tools/bake_font.py
.venv/bin/python firmwares/codex-pet/tools/test.py
.venv/bin/python scripts/firmware.py build codex-pet
scripts/bridge-service.sh stop
.venv/bin/python scripts/install-companion.py --workspace codex-pet
.venv/bin/python scripts/install-companion.py --workspace codex-pet --install
scripts/bridge-service.sh start
```

已备份设备只能使用受保护的应用区安装器。禁止擦除 Flash 或直接写合并镜像。创建/构建不切换设备或服务。当前设备保留原始引导程序和分区表，没有安装模板 Recovery。

## 实现与验证

- `tools/sequences.mjs` 定义产品序列；`tools/bake.mjs` 用固定版本原引擎按 60 Hz 生成 192×192 四位帧。六组共 4,287 帧，去重后的 DEFLATE/XOR 数据为 1,087,742 字节。
- `main/pet_behavior.c` 根据真实事件选择序列与循环尾段；`main/pet_ui.c` 提供纯绘制器和可逆的定点 smoothstep 位移。位置变化无需额外图像资源。
- `main/main.c` 独占直接 SPI 绘制、双 DMA 条带缓冲及绝对时间播放。协议与音频不在显示任务里运行。共享 40 MHz SPI 和 60 Hz 面板时序不变；背光采用四档活动策略，不启动 LVGL。
- `tools/bake_font.py` 使用 `../codex/assets/fonts/` 中现有的 OFL Montserrat 生成四位轮廓覆盖率；字形数据为 101,255 字节，另有 475 条字形记录。
- `main/pet_codec.c` 检查压缩边界、从关键帧寻址并追赶漏帧。自带 miniz 符号改名并进行链接检查，避免 ESP32-C3 ROM ABI 冲突。
- 协议、标题和提醒存储编译自 `../codex/main/companion_*.c`；修改共享契约时需验证两个消费者。

主机检查覆盖：全部帧与 Python zlib 对比、循环接缝端点完全一致、随机寻址、变化条带覆盖、不同位置和混合比例下分块/整屏绘制一致、位移反向连续、事件选择、重复提醒和快照不可变性。生成的源帧预览位于忽略目录 `build/previews/`。

停止服务后，USB 诊断支持 `PET|STATS|END`、`PET|CLIP|0|END`（0–5；-1 退出）、`PET|KEY|2|END`（UP=0、DOWN=1、OK=2、返回=3、画廊=4）和 `PET|SHOT|END`。

```bash
.venv/bin/python firmwares/codex-pet/tools/device_test.py --verify --perf --seconds 12 --shot reports/pet-home.png
```

命令发送合成中文任务、结果和声音，确认本次测试结果，再测量六组序列。截图是软件绘制器输出，不是 LCD 回读；截图期间暂停动画，并排除出性能统计。60 Hz 软件目标不等于已证明物理屏幕无撕裂扫描。测试后重新启动共享服务。

参见[来源与许可证](THIRD_PARTY.zh_CN.md)、[变更记录](CHANGELOG.zh_CN.md)和[验证结果](VALIDATION.zh_CN.md)。分别报告 Build、Host tests、Device tests 与 Unverified。

USB 诊断 `PET|IDLE|0..3600|END` 仅回拨闲置计时用于测试，不改变正式的一小时阈值。`--power` 使用该时钟注入检查边界、唤醒和确认回应规则。
